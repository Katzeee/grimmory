# Folio 手机端选字菜单

手机端的选字操作围绕文字选区展开。在手机宽度的 Readest 阅读页实测，菜单是贴近选区的紧凑横向工具条，选区靠近页面上缘时显示在选区下方。这个现场观察只说明该页面的实际呈现；下述源码和产品文档分别说明其实现与其他阅读器的交互约定。

Apple 的[编辑菜单设计规范](https://developer.apple.com/design/human-interface-guidelines/edit-menus)指出，iPhone 的编辑菜单由长按或双击选中内容触发，采用紧凑横排；默认出现在插入点或选区上方，空间不足时可移到下方，并应避免塞入过多自定义命令。规范没有把竖排书籍文字列为让 iPhone 触摸菜单改成纵向排列的例外；Readest 的纵向菜单是其产品实现，不能当作 iPhone 的通用行为。Apple 的 [Books 使用说明](https://support.apple.com/guide/iphone/annotate-books-iph17bf340c1/ios)描述了长按文字、拖动选区手柄、再执行高亮或添加笔记的流程；其示意图把高亮、笔记和翻译控件放在选区上方。Google 的 [Play Books 手机端说明](https://support.google.com/googleplay/answer/3165868?co=GENIE.Platform%3DAndroid&hl=en-GB)同样从长按、拖动选区手柄进入高亮颜色、笔记、翻译、定义和搜索动作，但未规定菜单的屏幕位置，因此不能据此主张底部固定工具条。

Readest 的参考版本是本地 `C:\Users\X\Documents\codes\readest` 的 `076556bd3ba82e68e2856d0f9e03105bc2568dd7`。其 [`getPosition`](https://github.com/readest/readest/blob/076556bd3ba82e68e2856d0f9e03105bc2568dd7/apps/readest-app/src/utils/sel.ts#L280-L374) 根据选区首末矩形和阅读框计算锚点：横排在选区上、下两端之间选择可见且空间合适的一侧，竖排则在左右两侧之间选择。随后 [`getPopupPosition`](https://github.com/readest/readest/blob/076556bd3ba82e68e2856d0f9e03105bc2568dd7/apps/readest-app/src/utils/sel.ts#L381-L417) 以锚点与菜单尺寸计算位置，并将四边约束在阅读区域内。[`Annotator.tsx` 第 229–257 行](https://github.com/readest/readest/blob/076556bd3ba82e68e2856d0f9e03105bc2568dd7/apps/readest-app/src/app/reader/components/annotator/Annotator.tsx#L229-L257) 将未标注选区菜单宽度设为可见工具数乘以响应式 44px，上限约 300px，高度为响应式 44px；[`AnnotationPopup.tsx` 第 55–87 行](https://github.com/readest/readest/blob/076556bd3ba82e68e2856d0f9e03105bc2568dd7/apps/readest-app/src/app/reader/components/annotator/AnnotationPopup.tsx#L55-L87) 把普通菜单排成可横向滚动的一行，竖排阅读时调整为纵向。较大的词典内容在窄屏改用底部面板，但[这是词典面板的分支](https://github.com/readest/readest/blob/076556bd3ba82e68e2856d0f9e03105bc2568dd7/apps/readest-app/src/app/reader/components/annotator/Annotator.tsx#L2139-L2164)，不是选字主菜单的布局。

触摸生命周期同样影响稳定性。Readest 在分页模式的触摸拖动中暂缓处理 `selectionchange`，等 `touchend` 再确定选区与显示菜单，避免拖动手柄时菜单反复闪现；滚动模式与 Android 原生应用保留即时处理路径，见 [`useTextSelector.ts` 第 923–957、1019–1050 行](https://github.com/readest/readest/blob/076556bd3ba82e68e2856d0f9e03105bc2568dd7/apps/readest-app/src/app/reader/hooks/useTextSelector.ts#L923-L1050)。

Folio 由此采用选区附近的紧凑操作菜单，而非将选字主菜单固定在页脚。横排与竖排文字使用同一套菜单和定位规则：选区上方有空间时显示在上方，否则移到下方，并约束在阅读区域内。[定位函数](../frontend/src/app/features/readers/folio/core/folio-selection-menu.ts) 将整个菜单限制在手机阅读区域内，[选区事件处理](../frontend/src/app/features/readers/folio/core/folio-view.service.ts) 在触摸拖动期间隐藏菜单，并在松手后更新一次。界面继续提供复制、划线和笔记，通过较小的图标条避免遮住阅读内容；点击别处、按 Escape 或打开设置与目录会清除选区菜单，因此操作条无需额外的关闭按钮。这些操作在 Web 应用里使用自定义菜单，不能等同于 iOS 原生编辑菜单。
